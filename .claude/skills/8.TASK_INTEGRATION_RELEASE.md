## Tujuan

Connect the frontend to the real API, prove all critical workflows and negative
authorization for four roles, verify security/accessibility/operability, and prepare a
reproducible release with migration and rollback notes.

## In scope

- Cross-check all 46 active API operations against frontend/backend/mocks.
- Synthetic seed/demo data for four roles and organization relationships.
- End-to-end critical workflows and error states.
- Security/privacy, accessibility/responsive, performance sanity, and observability review.
- Migration, backup/restore, Docker/Nginx/TLS, health/readiness, worker, and rollback notes.
- Release checklist and known limitations.

## Entry criteria

- [ ] OpenAPI validates and is stable for the candidate.
- [ ] Backend/frontend production builds pass independently.
- [ ] Migrations and deterministic synthetic seeds work from clean database.
- [ ] Auth/RBAC negative tests pass.
- [ ] Employee, attendance, approval, notification/access task acceptance criteria pass.
- [ ] No unresolved critical security/data-loss/concurrency defect.
- [ ] Environment and deployment target are identified without embedding secrets.

If entry criteria fail, return to the owning task instead of patching around the contract in
integration.

## Go/no-go criteria

### Go

- All critical/required checks pass.
- No unresolved critical/high security or data-integrity issue.
- Migrations, backup, rollback/forward-fix, environment, and monitoring are understood.
- Four-role and negative authorization E2E pass.
- Contract mismatch count is zero or explicitly approved with versioned plan.

### No-go

- Authentication/authorization bypass.
- Data loss/corruption or non-idempotent approval/notification job.
- Unrecoverable migration uncertainty.
- Secret/PII leakage.
- Broken production build/network exposure.
- Critical accessibility blocker for core workflow.
- Failed/unrun critical test presented without explicit risk acceptance.

## Rollback

Document:

- Previous known-good image/version/commit.
- Application rollback procedure.
- Migration rollback or forward-fix decision per migration.
- Nextcloud/file compensation implications.
- Cache/session invalidation implications.
- Verification after rollback.

Never assume container rollback automatically reverses schema or external file changes.
