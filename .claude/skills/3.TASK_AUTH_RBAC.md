## Tujuan

Implement login/logout, eight-hour JWT, Redis-backed active session, account lockout, and
four-role authorization so every later module can enforce route, role, ownership,
direct-report relation, and state-dependent actions.

## In scope

- `roles`, `users`, minimum `permissions`, and employee-user relation required by schema.
- Deterministic seed for `karyawan`, `atasan`, `hr`, `top_management`.
- Login, logout, JWT validation, Redis session cross-check, default rate limit.
- Five-consecutive-failure lockout returning `429 ACCOUNT_LOCKED`.
- Middleware/context identity and reusable authorization policies.
- Audit login/logout/failed or lockout events according to audit policy.
- Frontend login, auth initialization, safe redirect, role navigation, guards, 403 state,
  logout cleanup, and negative-access mocks/tests.

## Out of scope

- Do not add refresh token or refresh endpoint.
- Implement `/auth/me`, `/auth/me/password`, and public rate-limited self-reset exactly as
  defined in OpenAPI 0.4.0.
- Do not add SSO, MFA, self-registration, invitation, or password recovery email.
- Do not implement full permission administration; Task 6 owns it.

Frontend reload restores identity through `/auth/me`; storage strategy must still be recorded
and frontend role checks remain non-authoritative.

## Role and access baseline

| Role | Core scope |
|---|---|
| `karyawan` | Own profile/metrics/attendance/requests/notifications |
| `atasan` | Karyawan scope plus active approvals for direct reports |
| `hr` | Employee CRUD, dashboard/monitoring, final approval, master/access administration |
| `top_management` | Monitoring read-only; final decision only for HR requests; no Personal Metrics |

Authorization must combine:

```text
authenticated identity
  + role/capability
  + resource ownership
  + direct-report relationship
  + active approval stage
```

Route-level permission alone is insufficient.

## Failure matrix

| Condition | Expected result |
|---|---|
| Invalid body/credentials | Contract-defined `4xx`, generic safe message |
| Five consecutive failures | `429 ACCOUNT_LOCKED` |
| Missing/malformed Bearer | `401` |
| Expired/invalid JWT | `401`, local session cleanup |
| Redis session absent after logout | `401` |
| Valid identity without permission | `403`, session remains |
| Direct report mismatch | `403` or scoped not-found according to contract |
| Redis unavailable | Explicit secure failure; never bypass session check |

## Testing

### Backend unit/integration

- Valid login and correct claims/TTL.
- Invalid password counters 1–4.
- Fifth failure lockout and active-session invalidation.
- Concurrent failed logins do not lose increments.
- Successful login resets counter.
- Self-reset wrong credentials remain generic and rate-limited; success unlocks and revokes
  all sessions.
- Own-password change revokes all sessions and requires login again.
- Logout invalidates token immediately and is idempotent.
- Expired, malformed, wrong-secret, missing-session tokens fail.
- Role, own-resource, direct-report, HR, and Top Management policies.
- Negative access produces no forbidden side effect.
- Password/token/log redaction.

### Frontend

- Login validation, pending, invalid credentials, lockout, offline, 5xx.
- No protected-content flash.
- Safe redirect and open-redirect rejection.
- Menu/route/action matrix for four roles.
- Direct forbidden URL issues no sensitive request.
- 401 clears protected state; 403 does not logout.
- Logout during an in-flight request.

## Acceptance criteria

- [ ] Four role identifiers and approved minimum permissions seed idempotently.
- [ ] JWT expires in eight hours and requires active Redis session.
- [ ] Logout/lockout immediately invalidates prior active token.
- [ ] Fifth consecutive failure returns `429 ACCOUNT_LOCKED`.
- [ ] Route and row-level authorization follow the access matrix.
- [ ] Top Management exception is limited to final decision on HR requests.
- [ ] Frontend guards prevent protected flash and forbidden sensitive fetches.
- [ ] Passwords/tokens do not enter logs, responses, fixtures, or persistent UI state.
- [ ] Auth/OpenAPI/backend/frontend/mocks/tests remain synchronized.

## Exit gate

Do not begin protected employee features until authentication identity, session invalidation,
four-role seed, route guard, and reusable row-scope authorization tests are stable.
