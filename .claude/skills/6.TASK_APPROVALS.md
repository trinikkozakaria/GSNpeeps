## Tujuan

Implement Ketidakhadiran and Lembur requests with correct owner/approver scope, deterministic
routing, history, atomic decisions, supervisor delegation, and automatic escalation after
2x24 hours only from supervisor stage to HR.

## In scope

- Leave type, balance, request, approval tables.
- Overtime request and approval tables.
- HR master jenis izin operations from API Contract.
- Create request, own history, approver inbox, detail, decision, delegation, overtime recap.
- Required leave document and optional overtime document.
- Cuti, Izin, Perjalanan Dinas conditional data.
- Supervisor -> HR, direct HR, and HR -> Top Management flows.
- Worker auto-escalation for stale `menunggu_atasan`.
- Durable history for approve/reject/delegate/auto-escalate.
- Frontend request forms, lists, detail, timeline, decision/delegation, recap.

## Out of scope

- Overtime compensation calculation.
- Travel budget approval.
- Benefit integration.
- General workflow builder or arbitrary approval levels.
- Automatic escalation from HR to Top Management.
- Public notification creation endpoint.
- Editing a request after decision unless explicitly defined by contract.

## Routing matrix

| Applicant | First active stage | Final stage |
|---|---|---|
| Karyawan with direct supervisor | Atasan langsung | HR |
| Karyawan without supervisor | HR | HR |
| Atasan submits own request | HR | HR |
| HR submits own request | Top Management | Top Management |

Rules:

- Top Management only decides HR-owned requests.
- Atasan only sees/decides direct-report requests at active supervisor stage.
- Applicant only sees own request unless also authorized approver.
- Reject ends the workflow and requires a note.
- Supervisor approve moves to `menunggu_hr`.
- Delegate and auto-escalate move supervisor stage to HR and preserve history.

## State and invariants

Use exact contract/schema status values. Model allowed transition explicitly:

```text
draft/submitted (if defined)
  -> menunggu_atasan
      -> approved by atasan -> menunggu_hr
      -> delegate           -> menunggu_hr
      -> auto_escalate      -> menunggu_hr
      -> reject             -> rejected

direct HR route
  -> menunggu_hr
      -> approve -> approved
      -> reject  -> rejected

HR applicant
  -> menunggu_top_management
      -> approve -> approved
      -> reject  -> rejected
```

- Use transaction plus row lock or conditional update.
- Only one concurrent decision wins.
- Losing request returns `409 ALREADY_DECIDED`.
- Derive actor/role/scope server-side.
- Use server time for submission, decision, and SLA.
- Store immutable approval history; do not overwrite prior step.

## Notification handoff

This task must emit/durably record domain events needed by Task 6:

- Request submitted to active approver.
- Supervisor approved and forwarded to HR.
- Request delegated to HR.
- Request auto-escalated to HR.
- Final approved/rejected to applicant.
- Next active approver notification.

Define deterministic event inputs now; Task 6 owns notification storage/query UI. Do not add
a public create-notification endpoint.

## Failure matrix

| Condition | Expected behavior |
|---|---|
| Missing required leave document | `422`, no upload/request |
| Missing Perjalanan Dinas detail | `422` field errors |
| Invalid overtime interval | `422`, no request |
| Unauthorized applicant/detail | Scoped `403/404` according to contract |
| Unrelated supervisor decision | `403`, no side effect |
| Reject without note | `422` |
| Two decisions | One success; loser `409 ALREADY_DECIDED` |
| Upload succeeds, DB fails | File compensation/orphan reconciliation |
| Worker repeated | No duplicate transition/history/event |
| HR/Top Management stage overdue | No auto-escalation |
