## Tujuan

Implement secure photo attendance for WFO/WFH/WFA, server-authoritative time, WFO radius,
live monitoring, reports/exports, camera fallback, and three-month photo retention without
deleting attendance history.

## In scope

- `attendances` migration/domain/repository/service/API.
- Check-in and checkout according to API Contract.
- JPG/PNG photo upload, GPS, address, local watermark time, server/network time, work mode.
- 100-meter office radius only for WFO.
- Duplicate check-in and checkout-without-check-in prevention.
- Camera UI and watermarked fallback upload.
- HR live feed, reports, filters, XLSX/PDF export.
- Top Management read-only monitoring.
- Daily worker deleting old Nextcloud photos and setting `foto_url = NULL`.

## Out of scope

- Attendance reminders.
- Facial recognition, biometric matching, anti-spoofing, or employee surveillance additions.
- Offline acceptance that rewrites server time.
- WFH/WFA radius restriction.
- Hard deletion of attendance history.
- Direct browser-to-Nextcloud upload.
- Payroll calculation from attendance.

## Attendance invariants

```text
WFO -> photo + GPS + selected active office_location_id -> trusted distance <= 100 m
WFH -> photo + GPS/location metadata, no office-radius rejection
WFA -> photo + GPS/location metadata, no office-radius rejection
```

- Use server time as `waktu_network` and business truth.
- Regular workdays are Monday-Friday in `Asia/Jakarta`; weekends return
  `422 NON_WORKING_DAY`.
- Check-in at 09:00 is on time; after 09:00 is `terlambat`.
- Checkout before 18:00 is accepted and recorded as `pulang_cepat`.
- Use client/local time only in the watermark/presentation field required by contract.
- Do not trust client-submitted computed distance, attendance date, or authoritative time.
- Prevent a second check-in for the same employee/business day.
- Prevent checkout when no open attendance exists.
- Apply consistent timezone/day boundary from approved configuration.
- Store file URL/path only after successful Nextcloud upload and database transaction logic.

## Failure matrix

| Condition | Expected behavior |
|---|---|
| Camera denied/unavailable | Explain and offer approved fallback upload |
| Geolocation denied/unavailable/timeout | Block/handle according to contract with actionable message |
| WFO >100 m | `422 OUT_OF_RADIUS`, preserve recoverable capture where safe |
| WFH/WFA far from office | No radius rejection |
| Duplicate check-in | Contract-defined conflict/validation error, no duplicate row/file |
| Checkout without open check-in | Business error, no mutation |
| Invalid/oversize file | Reject before Nextcloud/DB |
| Nextcloud upload failure | No attendance row with invalid URL |
| DB failure after upload | Compensate or queue orphan cleanup |
| Retention missing file | Idempotent reconciliation, attendance row retained |

## Acceptance criteria

- [ ] WFO radius is calculated server-side and limited to 100 meters.
- [ ] WFH/WFA are not rejected by office radius.
- [ ] Server time is authoritative; local time is watermark/presentation only.
- [ ] Duplicate check-in and checkout without check-in cannot create invalid state.
- [ ] Only valid JPG/PNG up to 5 MB reach storage.
- [ ] HR has live feed/report/export; Top Management is read-only.
- [ ] Karyawan/Atasan cannot access global feed/report.
- [ ] Camera failure has a usable watermarked upload fallback.
- [ ] Retention removes files older than three months and sets URL NULL without deleting rows.
- [ ] No reminder attendance feature is introduced.

## Exit gate

Release integration must not proceed until storage compensation, concurrent attendance
invariants, role scope, camera/GPS fallback, and retention repeat-run tests pass.
