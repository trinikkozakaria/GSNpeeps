## Tujuan

Make PostgreSQL the employee single source of truth and deliver organization master data,
HR employee CRUD, document storage, personal profile/metrics, and HR/Top Management dashboard
with correct privacy and read-only boundaries.

## In scope

- Departments, positions, employee core and all approved employee detail tables.
- Master department/position read operations.
- Employee list, detail, create, update, soft-deactivate/delete, export.
- Employee document upload/list through backend to Nextcloud.
- Own profile and current personal metrics.
- HR/Top Management aggregate dashboard and org chart.
- Frontend list/detail/form/profile/dashboard, filters, pagination, upload, and export UX.

## Out of scope

- Karyawan self-service profile editing.
- Hard delete of employee history.
- Recruitment/hiring workflow.
- Recruitment Cost and Benefit.
- Payroll processing; only approved current-month salary display and aggregate payroll cost.
- Document upload directly from browser to Nextcloud.
- Fields or endpoints not present in approved contract/schema.

## Access mapping

| Capability | Karyawan | Atasan | HR | Top Management |
|---|---|---|---|---|
| Own profile/metrics | Own | Own | Own | Not available |
| Employee database | No | No | CRUD + export | Read-only |
| Employee documents | No global access | No global access | Upload/read | Read-only only if contract permits |
| HR dashboard/org chart | No | No | Full | Read-only |
| Mutation controls | No | No | Yes | No |

Return only fields appropriate to operation and role. UI hiding is not authorization.

## Data scope

Implement the approved 15-table employee/organization group:

```text
departments
positions
employees
employee_addresses
employee_ktp
employee_contracts
employee_bpjs
employee_npwp
employee_emergency_contacts
employee_education
employee_position_history
employee_salaries
employee_documents
roles/users relation as defined by schema
```

Read Database Schema v1.1 for exact fields, types, nullability, unique constraints, foreign
keys, check constraints, and indexes. Do not derive columns from the UI summary.

## File and export rules

- Browser sends multipart to backend, never Nextcloud.
- Validate client-side for UX and backend-side for authority.
- Generate storage object names server-side.
- Never expose Nextcloud credential or permanent public link without explicit decision.
- Export only data/columns permitted by contract and role.
- Do not cache export blobs or employee sensitive data persistently.
- Revoke frontend object URLs after use.
- Audit required upload/download/export actions without storing document content.

## Testing

### Database/repository

- Uniqueness, FK, check constraints, index-supported filters, soft-delete exclusion.
- Supervisor/department-position relations and cycle prevention.
- Salary uniqueness per employee/period.
- Migration up/down-one/re-up.

### Service/API

- HR CRUD happy/error paths and audit transaction.
- Top Management read-only negative mutations.
- Karyawan/Atasan forbidden employee database/document access.
- Pagination/filter/order and export authorization.
- Upload valid, oversize, MIME/signature mismatch, Nextcloud failure, DB failure compensation.
- Profile ownership/current salary period.
- Dashboard formula/period/no-data tests.

### Frontend

- URL filter/pagination and cancellation.
- Form client/server validation, double submit, conflict.
- Role variants and no-sensitive-fetch assertion.
- Upload/download cleanup.
- Dashboard accessible alternatives and mobile layout.
- Coming Soon limited to three approved metrics.

## Acceptance criteria

- [ ] All employee/organization tables, constraints, indexes, and migrations match schema.
- [ ] HR can CRUD, upload/list documents, and export.
- [ ] Employee deletion is soft and history remains.
- [ ] Karyawan/Atasan cannot access global employee data/documents.
- [ ] Top Management can monitor but cannot mutate.
- [ ] Own profile/metrics are correctly scoped; Top Management has no Personal Metrics.
- [ ] File flow is backend-to-Nextcloud, approved type, maximum 5 MB, and compensating.
- [ ] Dashboard uses real approved metric semantics and accessible visualization.
- [ ] Only Hiring Progress, Recruitment Cost, and Benefit are Coming Soon.
- [ ] Contract, mocks, tests, and UI states are synchronized.

## Exit gate

Do not start Attendance/Approval integration until employee identity, supervisor relation,
role-linked user, storage boundary, and organization references are stable and tested.
